## Источник истины по дизайну

Пакет `design_handoff_charva/` — двадцать `.dc.html` плюс README на 626 строк.

```
Решения владельца (монорепо, стек, порты, без Docker, VPS)
  > README §1 §8 §10        — архитектура, API, поведение адаптива
  > прототипы .dc.html      — конкретные значения: цвета, пиксели, тексты
  > README §7               — черновик схемы БД (набросок, заменён разделом 3 PLAN.md)
  > поведение прототипов    — почти отсутствует либо дефектно, никогда не авторитет
```

**Прототипы выигрывают по значениям, README — по поведению и структуре.** Обратное правило
silkgrain («где проза противоречит коду, выигрывает код») здесь не работает: там проза была
остатком отклонённого направления, здесь прототипы **усечены**, а не противоречивы. Признак —
на Choice массивы `globalChips` и `umrahChips` заполнены данными, а тело рендера пустое.

`.dc.html` — это DSL дизайн-инструмента: `<x-dc>`, `<sc-for>`, `<sc-if>`, `<dc-import>`,
`{{ }}`, `style-hover=`, класс `Component extends DCLogic` с `state`/`setState`/`renderVals()`.
Воспроизводим **визуальный результат**, а не структуру прототипа. `renderVals()` возвращает
мешок уже посчитанных строк стилей — в React это состояние плюс классы, а не порт один в один.

`support.js` и `image-slot.js` **не переносятся ни строчкой**. `support.js` — генерируемый
рантайм превью: он не объявляет ни одного кастомного элемента, не содержит CSS-сброса, не грузит
шрифты и инжектит только служебные стили с префиксом `sc-`. `image-slot.js` объявляет один
элемент с shadow DOM, из которого в проде нужны лишь `object-fit:cover` и размер обёртки.
Переносится единственное — `@font-face`, `box-sizing`, цвета ссылок и `::selection` из
`<helmet>` каждой страницы.

Пакет дизайна **read-only**. Никогда не редактировать, не форматировать и не линтить — он
исключён в `.prettierignore`, `.gitattributes` и каждом конфиге ESLint.

## Локальное окружение — прочитать, это не стандартная настройка

|            | Ожидание        | Реальность на этой машине                                                 |
| ---------- | --------------- | ------------------------------------------------------------------------- |
| База       | MySQL 8         | XAMPP держит **MariaDB 10.4 на 3306**, silkgrain — **MySQL 8 на 3307**    |
| Контейнеры | Docker Compose  | **ни Docker, ни WSL, ни прав администратора**                             |
| ffmpeg     | нужен для видео | стоит портативно: `.services/ffmpeg/bin/`, ставится `pnpm setup:services` |
| Node       | —               | v26.4.0, npm 11.17.0, pnpm 10.34.5                                        |

Решение:

- **MySQL 8.0.42 на порту 3308**, портативным ZIP под `.services/`. 3306 и 3307 не трогаем —
  там чужие проекты. Дев и прод на MySQL 8.0.x, диалектного дрейфа нет.
- **Mailpit** (SMTP 1026, UI `http://localhost:8026`) и **ffmpeg** — тоже портативными
  бинарниками под `.services/`. Ничего не пишется в реестр, PATH и Program Files.
- `docker/docker-compose.dev.yml` держится актуальным и используется CI. Порты, пароли и
  версии в нём и в `scripts/dev-setup.ps1` совпадают намеренно.

```powershell
pnpm setup:services                                  # установить и запустить всё
powershell -File scripts/dev-setup.ps1 -Action status
powershell -File scripts/dev-setup.ps1 -Action stop
powershell -File scripts/dev-setup.ps1 -Action remove
```

### Карта портов — Charva сознательно ушла со всех значений по умолчанию

На этой машине параллельно работает проект `silkgrain`, и он занимает ровно те порты, которые
Vite, Fastify и Mailpit выбирают сами: 5173, 5174, 4173, 3001, 1025, 8025. Плюс XAMPP держит 3306. Поэтому Charva не использует ни одного значения по умолчанию — иначе два проекта нельзя
запустить одновременно, а обнаруживается это не сразу: чужой сервер на 3001 отвечает на
`/health` как ни в чём не бывало, и запрос уходит не туда.

| Что        | Charva                     | Занято чужим                           |
| ---------- | -------------------------- | -------------------------------------- |
| API        | **3002**                   | 3001 — silkgrain                       |
| web-choice | **5180** (preview 4180)    | 5173, 4173 — silkgrain                 |
| web-global | **5181** (preview 4181)    | 5174 — silkgrain admin                 |
| web-umrah  | **5182** (preview 4182)    | —                                      |
| admin      | **5183** (preview 4183)    | —                                      |
| Storybook  | **6180**                   | 6006 — значение по умолчанию           |
| MySQL      | **3308**                   | 3306 — XAMPP MariaDB, 3307 — silkgrain |
| Mailpit    | SMTP **1026**, UI **8026** | 1025, 8025 — silkgrain                 |

Значения продублированы в `.env.example`, `apps/*/vite.config.ts`, `docker-compose.dev.yml` и
`scripts/dev-setup.ps1`. Расхождение между двумя последними ловит
`apps/api/src/config-parity.test.ts`.

### Windows-грабли, которые уже стоили времени в silkgrain

- **Скрипты PowerShell держать в чистом ASCII.** PowerShell 5.1 читает файлы без BOM как ANSI,
  и UTF-8 тире превращается в байты, которые парсер принимает за разделитель строки; скрипт
  падает с синтаксическими ошибками, указывающими на посторонние строки. Проверка входит в
  приёмку Фазы 0:
  `[IO.File]::ReadAllBytes('scripts/dev-setup.ps1') | ? { $_ -gt 127 }` обязана вернуть пустоту.
- **pnpm 10 блокирует lifecycle-скрипты.** `esbuild`, `unrs-resolver`, `sharp` и
  `@node-rs/argon2` нуждаются в своих; они в белом списке `onlyBuiltDependencies` в
  `pnpm-workspace.yaml`. Без этого Vite, tsup и обработка изображений падают в рантайме на
  отсутствующем бинарнике платформы.
- **У MariaDB из XAMPP нет `STRICT_TRANS_TABLES`.** Наш инстанс выставляет его явно вместе с
  `ONLY_FULL_GROUP_BY`. Никогда не направлять приложение на 3306.
- `sql_mode` записан в трёх местах, которые обязаны совпадать: `scripts/dev-setup.ps1`,
  `docker/docker-compose.dev.yml` и генерируемый `.services/my.ini`. Изменение требует
  перезапуска MySQL.
- **sharp нужен libvips**, готовый бинарник покрывает **glibc x64** — на VPS Ubuntu, не Alpine.
- **Никогда не открывать файл на запись в том же выражении, в котором он читается.**
  `open(p,'w').write(open(p).read().replace(...))` в Python обрезает файл **до** того, как
  выполнится чтение: аргумент вычисляется после открытия. Так в Фазе 6 обнулились оба файла
  копии `web-umrah`, и восстанавливать их пришлось целиком. Читать в переменную, потом писать —
  или пользоваться `Edit`.
- **Не расширять ignore-шаблоны на исходники.** `*.sql` в `.gitignore` был написан для дампов и
  съел `apps/api/src/db/migrations/*.sql`: в репозитории лежал `meta/_journal.json` со списком
  из двух миграций и ни одного файла, который он называет. Чистый клон применял ноль миграций,
  отчитывался успехом, и все db-тесты шли по пустой базе. Миграции возвращены по имени.

## Непререкаемые инженерные правила

**Деньги — целые минорные единицы в `BIGINT`.** Никаких `float` и `DECIMAL` в бизнес-логике.
Единственное место, форматирующее валюту, — `Money` в `packages/contracts`; ESLint запрещает
`new Intl.NumberFormat` где-либо ещё. Каждая сумма в API — целое плюс отдельное поле валюты.

**Одна Zod-схема, два потребителя.** Схемы живут в `packages/contracts`, питают
`fastify-type-provider-zod` на бэкенде и `zodResolver` на фронтенде. Схемы входа и выхода всегда
раздельны и связаны через `.pick()` / `.omit()` / `.extend()`, никогда двумя рукописными
копиями. Все входные — `.strict()`.

**У каждого маршрута обязательна схема ответа.** Это не аккуратность, а механизм: именно через
неё запрет цен Umrah становится структурным. `umrah_trips.price_minor` существует для админки,
но в публичной схеме ответа такого поля нет, а провайдер типов использует схемы ответа как
сериализатор — случайный `select *` обрезается на проводе. Соглашение однажды забудут,
сериализатор — нет. Тест рекурсивно обходит JSON каждого публичного маршрута и падает на любом
ключе, похожем на цену.

**Клиент никогда не присылает цену.** `POST /builder/quote` — единственный авторитет. Клиент
считает мгновенно **той же чистой функцией** из `packages/contracts`, получив таблицу ставок из
`GET /builder/config`, поэтому разойтись не с чем: второй реализации не существует. При отправке
заявки сервер пересчитывает из БД и игнорирует всё, что прислал клиент.

**Формула сборщика ключуется стабильными ASCII-кодами.** `dest_ashgabat`, `nights_7`,
`hotel_3star`, `pax_6_10`. Код неизменяем после первой ссылки. В прототипе ключами служили
отображаемые строки `3 ★` и `3–5` — с настоящим символом звезды и en-dash; переименование
варианта в админке молча сломало бы расчёт. `numeric_value` (ночи, человек) отделён от
`price_modifier_minor` (ставка отеля): `7 дней` — не цена.

**Ставки отелей в сборщике и цены отелей в каталоге — разные колонки**, хотя сидовые значения
совпадают. Иначе редактор, поправивший цену одного отеля, молча переоценит все открытые расчёты.

**Пароли — Argon2id** через `@node-rs/argon2` (готовые NAPI-бинарники ставятся на этой машине
без сборочных инструментов), параметры OWASP: 19 МиБ, t=2, p=1. Никогда bcrypt.

**Сессии:** access-JWT 15 мин в памяти + refresh 48 случайных байт (не JWT), хранимый
HMAC-SHA256-дайджестом, ротируемый при каждом использовании; повтор отозванного отзывает всё
семейство. Кука `HttpOnly; Secure; SameSite=Strict; Path=/api/v1/admin/auth`. **API админки
отдаётся same-origin по `admin.charva-travel.com/api`** через nginx в тот же upstream — поэтому
кука не уезжает на публичные сайты и CSRF во многом исчезает без double-submit токена.

**Номера паспортов шифруются при хранении** (AES-256-GCM, ключ в окружении), отсутствуют в
списочных ответах, расшифровываются только явным действием «показать», которое пишет строку в
`audit_log`. Это самое чувствительное поле в системе.

**EXIF удаляется со всех загружаемых изображений.** Это фотографии паломников, а EXIF несёт GPS.

**SQL только через Drizzle.** Никакой конкатенации строк. Миграции только через
`drizzle-kit generate`, forward-only: «откатить» означает `pnpm db:reset` в разработке и
восстановление предделойного дампа в проде.

**Никаких заглушек.** Ничего, помеченного `// TODO: сделаю позже`, не считается готовым. Если
функция не влезает в текущую фазу — она не создаётся вовсе, а уезжает в `BACKLOG.md`.

## Правила, специфичные для этого проекта

**Тема — окружение, а не проп.** Все цветовые токены выпускаются CSS-переменными под
`[data-theme="global|umrah|choice"]` на `<html>`; Tailwind ссылается на `var(--c-*)`. Ни один
компонент `packages/ui` не принимает `theme` и не содержит `if (theme === 'umrah')`. Пропами
берутся только реально расходящиеся геометрия и поведение. Это разница между общей библиотекой и
тремя копиями с переключателем.

**Разметка, встретившаяся дважды, живёт в `packages/ui`.** Три сайта — это три бандла и три
набора одинаковых багов, если компонент скопирован, а не вынесен.

**Адаптив, i18n и доступность пишутся вместе с разметкой**, а не отдельной фазой потом.
Классы `lap:` / `tab:` / `mob:` появляются в том же коммите, что и экран. В silkgrain это же
решение принято как D-19 после того, как ретрофит был оценён в 30–40 часов.

**Никаких `<div onClick>`.** Фильтры, табы, точки слайдера, строки таблиц, шаги сборщика — всё
это `<button>`, `role="tab"`, `role="radio"` или `<details>`. `outline: none` без видимой замены
фокуса — ошибка линтера. В прототипах не семантичен ни один интерактивный элемент; это
исправляется при написании, а не аудитом в конце.

**Счётчики — производные, а не хранимые поля.** Число фото и видео у группы, «Показано N из M»,
средняя оценка, процент рекомендаций — всё `COUNT` и `AVG`. В прототипе хранимые счётчики уже
разошлись с данными: у группы указано `videos: 4` при трёх роликах и `photos: 38` при восьми
подписях.

**Чипы фильтров строятся из данных.** `SELECT DISTINCT` по опубликованным строкам. Это
структурно чинит пропавший чип `Jidda` на `/ziyarat` (город в данных есть, чипа нет) и
гарантирует, что ни один чип не приведёт к пустой сетке.

**Текущий рейс умры выводится, а не запоминается.** Берётся рейс со статусом `open|full|closed`
и ближайшей будущей `depart_at`; `is_current` существует только как ручное переопределение.
Флаг, который админ должен не забыть переставить, окажется неверным ровно на той неделе, когда
владелец в отъезде. Статус вычисляется при чтении и дописывается кроном: чтение остаётся верным
даже при умершем кроне, а запись нужна, чтобы админские списки не расходились с сайтом.

**Дата вылета существует в одной строке БД.** В прототипе `2026-09-18T06:00:00Z` зашита в JS
трёх файлов, а строка `18.09.2026` — ещё примерно в восьми местах. Тест: смена `depart_at` в
админке обязана сдвинуть все даты на трёх сайтах за одну перезагрузку.

**Строки интерфейса — версионируемые JSON-файлы в репозитории, не БД.** README §9 просит экран
«Переводы» с таблицей ключей; копия интерфейса меняется вместе с вёрсткой, ревьюится вместе с
ней и не должна иметь возможности сломать страницу в рантайме. В базе только **контент**.

**Многоязычный контент — JSON-колонки** `{ru,en,tr}` для Global и `{tm,ru}` для Umrah, не
таблицы `*_translations`. Разрешается единственной чистой функцией `pickLocale()`, валидируется
`JSON_SCHEMA_VALID`. Сортировки и фильтры вешаются только на скалярные колонки — в JSON лежит
исключительно отображаемый текст.

**Мёртвые данные трёх тарифов умры вычищены, а не закомментированы.** В прототипе лежит
заполненный `packagesUnused` с ценой `8 575 TMT`, у мест зиярата есть поле `pack`
(«Plus we VIP»), а лид-абзацы Program и Route ссылаются на тарифы. README §5 однозначен: умра
одна, цен на сайте нет. «Оставим на всякий случай» — это ровно то, как цена однажды попадает
на страницу.

**`content_slots` — это то, что делает проект собираемым без фотографий.** Все 151 бриф
`<image-slot>` живут строками БД со статусом; `ImageSlot` рисует фирменную заглушку с
собственным брифом, пока `media_id IS NULL`. Отсутствие снимков — видимый чек-лист в админке, а
не недокументированный блокер. Ни один стоковый файл не уезжает в прод незаметно:
`is_placeholder=1`, и выкладка блокируется, пока список не пуст.

## Дефекты прототипов — исправлены намеренно, не воспроизводить

Полный список в PLAN.md §0.5. Те, что чаще всего пытаются «вернуть как в макете»:

| В прототипе                                                           | В реализации                          |
| --------------------------------------------------------------------- | ------------------------------------- |
| Полоса набора — литерал `width:73%`                                   | считается из `33/45` = 73,3%          |
| `Math.ceil` на Choice и Signup, `Math.floor` на главной Umrah         | везде `floor`, один `CountdownTimer`  |

## Соглашения

- Conventional Commits, проверяются commitlint. Разрешённые скоупы: `api`, `choice`, `global`,
  `umrah`, `admin`, `ui`, `contracts`, `config`, `db`, `docs`, `ci`, `deps`, `repo`.
- TypeScript `strict` плюс `noUncheckedIndexedAccess` и `exactOptionalPropertyTypes`.
  `any` и `@ts-ignore` — ошибки линтера; `@ts-expect-error` требует описания.
- Каждый пакет типизируется через `tsc --noEmit`; эмит делают tsup (пакеты, api) или Vite (SPA).
- Импорты без расширений — всё бандлится, `moduleResolution: "Bundler"` их разрешает.
- **Документы по-русски, комментарии в коде по-английски.** Так написаны все триста с лишним
  исходников; правило изначально говорило обратное и разошлось с практикой к концу Фазы 1.
  Длинные пояснительные блоки там, где решение неочевидно, приветствуются: в этом проекте много
  мест, где «правильно» расходится с макетом, и через месяц причина не восстанавливается.
- Никогда не коммитить: `.env`, дампы БД, `node_modules`, `uploads/`, `.services/`.
