## Контекст

Есть дизайн-пакет на три публичных сайта и одну общую админ-панель. Пакет high-fidelity: цвета, размеры и отступы финальные, но это **HTML-прототипы дизайн-инструмента**, а не код. Задача — воссоздать их в React с нормальными компонентами, роутингом и данными из API.

| Домен                      | Что                                            | Языки                     |
| -------------------------- | ---------------------------------------------- | ------------------------- |
| `charva-travel.com`        | Choice — сплит-экран выбора бренда             | RU, EN, TR, TM            |
| `global.charva-travel.com` | Charva Travel Global — 9 маршрутов + детальные | RU, EN, TR (по умолч. RU) |
| `umra.charva-travel.com`   | Charva Umrah — 6 маршрутов + детальные         | TM, RU (по умолч. TM)     |
| `admin.charva-travel.com`  | Админка на оба сайта                           | RU                        |
| `api.charva-travel.com`    | Node.js REST API                               | —                         |

Цель: два работающих публичных сайта, где **весь** контент редактируется из админки без деплоя, плюс работающие формы заявок с уведомлением менеджеру.

**Решения владельца, принятые до начала:** монорепо как в `silkgrain`; локальная БД — свой портативный MySQL 8 под `charva/.services`; порядок фаз backend-first; детальные страницы делаем для всех сущностей (туры, отели, статьи, места зиярата); видео — **самохостинг на VPS**; админка — shadcn/ui поверх Radix; до появления реальных фото работаем на временных стоковых. Эта сессия производит **только документы**.

### 0.4 Чего в пакете нет

1. **Ни одной реальной фотографии.** 151 слот `<image-slot>` с русским брифом, что за кадр нужен.
2. **Ни одного медиазапроса.** Каждая страница `min-width:1280px`. Адаптив описан только текстом в README §10.
3. **Ни одной CSS-переменной.** Все цвета — инлайновые литералы; имена токенов есть только в таблице README.
4. **Ни одной рабочей формы.** Нет `<form>`, контролируемых инпутов, валидации, submit, состояний успеха и ошибки. Чекбоксы — стилизованные `<span>`, кнопки отправки — `<a href="#">`.
5. **Ни одного плеера.** Кнопки play — декорация с `pointer-events:none`.
6. **Ни одной детальной страницы.** Все карточки ведут на `#`.
7. **Ни строчки i18n.** Переключатели языка переключают только сами себя.

### Фаза 0 — Фундамент — 12–16 ч

`git init` и ignore-списки · перенос пакета дизайна в корень отдельным коммитом, read-only во всех линтерах · pnpm workspaces + Turborepo · `packages/config` копией из silkgrain · собираемые пустые скелеты всех семи пакетов · husky + lint-staged + commitlint (скоупы `api, choice, global, umrah, admin, ui, contracts, config, db, docs, ci, deps, repo`) · `dev-setup.ps1` (MySQL 3308, Mailpit, ffmpeg) · `docker-compose.dev.yml` · `.env.example` + `loadEnv` на Zod, отвергающий заглушки при `NODE_ENV=production` · `CLAUDE.md`, `STATE.md`, `QUESTIONS.md`, `BACKLOG.md`.

**Acceptance:** `pnpm install && pnpm typecheck && pnpm lint && pnpm build` зелёные с чистого клона; `dev-setup.ps1 -Action install` поднимает MySQL на 3308, не трогая 3306 и 3307, `-Action remove` не оставляет следов вне `.services/`; `docker compose config` валиден; `dev-setup.ps1` побайтово ASCII — `[IO.File]::ReadAllBytes(...) | ? { $_ -gt 127 }` ничего не возвращает.

### Фаза 1 — Дизайн-система — 38–48 ч

Ключевое решение фазы: **тема — окружение, а не проп.** Все цветовые токены выпускаются CSS-переменными под `[data-theme="global|umrah|choice"]` на `<html>`, Tailwind ссылается на `var(--c-*)`. Следствие: ни один компонент `packages/ui` не принимает `theme` и не содержит `if (theme === 'umrah')`. Пропами берутся только реально расходящиеся геометрия и поведение.

Токены трёх палитр и производные (радиусы, тени, тайминги) · Tailwind preset с контейнером 1480/60, брейкпоинтами `lap:` ≤1279 / `tab:` ≤1023 / `mob:` ≤767 и тремя сведёнными keyframes (`dropIn`, `pulse`, `fadeUp` вместо пяти) · шрифты Stolzl из Bakar, 5 весов · **тест покрытия глифов** (D-14) · **аудит контраста и правка шести токенов** (D-3) · примитивы, кнопки, формы с настоящим `<input type="checkbox">` · `Chip`/`FilterChipRow`, `Badge`, `StarRating`, `StatStrip`, `ProgressBar` с `role="progressbar"` · `Card`, `Accordion`, `Tabs` с roving tabindex, `Modal`/`Lightbox` с ловушкой фокуса · **`Carousel`** — один компонент на все четыре слайдера: пауза при наведении и фокусе, остановка при `prefers-reduced-motion`, **сброс таймера при ручной навигации**, `aria-roledescription`, индикаторы `variant="rail"|"dots"` · `Img` · **`ImageSlot`** — фирменная заглушка с брифом, пока `content_slots.media_id IS NULL` (D-21) · **`CountdownTimer`** — один на Umrah и Choice, `floor`, пауза по `visibilitychange`, `aria-live` раз в минуту, а не в секунду · `SiteNav` (остров + бургер на `tab:`) и `SiteFooter` — по одному компоненту, управляются конфигом · Storybook 8 + `addon-a11y`.

**Acceptance:** Storybook собирается, каждый компонент отрендерен в обеих темах и совпадает с прототипом при 1280px; `tokens.test.ts` зелёный — все текстовые пары ≥ 4.5:1 либо явно записанное исключение; тест глифов зелёный на всём четырёхъязычном наборе; клавиатурой достижим каждый интерактивный элемент, Esc закрывает оверлеи; при `prefers-reduced-motion: reduce` ни одна карусель не крутится.

### Фаза 2 — Данные — 32–40 ч

`packages/contracts`: `Money` (BIGINT в минорных единицах, USD и TMT), фабрики `i18n2/i18n3/i18n4`, **чистая `pickLocale(value, lang, chain)` с тестами**, `SITE_LANGS`, коды ошибок, пагинация · Drizzle-схема на 27 таблиц (§3) с `JSON_SCHEMA_VALID` на каждой i18n-колонке и CHECK на места · индексы, включая функциональные по `JSON_UNQUOTE(JSON_EXTRACT(title,'$.ru'))` там, где админские списки сортируются по локализованному заголовку · миграции forward-only + `db:reset`, отказывающийся работать со схемой не на `charva*` · `scripts/extract-design-data.mjs` — вытащить из 20 прототипов все зашитые массивы в `docs/design/content.json`, сверив результат с уже написанными `docs/design/SCREENS.md` и `photo-brief.md` · сиды Global, Umrah, сборщика и `content_slots` · временные стоковые фото по брифам с `source='stock'`, `attribution` и `is_placeholder=1`.

**Acceptance:** `pnpm db:reset && db:migrate && db:seed` дважды подряд начисто; `db:seed` отказывается сидировать непустую БД; тесты ограничений доказывают, что правила держит **база**, а не приложение (отрицательные места, две строки `is_current`, кривой i18n-JSON, обрезание строки при `STRICT_TRANS_TABLES`); `quote({})` возвращает ровно `1 296 $`; `rg "2026-09-18|18\.09\.2026" apps packages` совпадает только с файлом сидов.

### Фаза 3 — Публичный API — 32–40 ч

Приложение Fastify (helmet, CORS белым списком без wildcard, compress, rate-limit, request-context, pino, graceful shutdown) · единый конверт ошибки · `fastify-type-provider-zod`, **response-схема обязательна у каждого маршрута** — это механизм, делающий запрет цен Umrah структурным (D-12) · middleware локали, проверяющий язык против набора **конкретного сайта** · модули `global`, `umrah`, `builder`, `leads` · композитные `/global/home` и `/umrah/home` — иначе главная делает девять запросов на плохом канале · `GET /builder/config` + `POST /builder/quote`, формула — **одна чистая функция в `packages/contracts`**, импортируемая обеими сторонами (D-11) · пять слоёв антиспама без капчи (D-19) · кеш в процессе 60 с + `ETag` + счётчик поколений, сбрасываемый записью из админки · `/img/:name?w=` и статика · `/health`, `/ready`, `/docs`.

### Сборщик (3) — главная правка

README смешивает в `price_modifier` две разные вещи: «этот вариант стоит X» и «этот вариант означает число N». `7 дней` — не цена.

```
builder_steps    code(dest|dates|hotel|food|transport|activities|people|guide|submit),
                 kind ENUM('single','multi','form'), title/hint JSON, sort_order, is_required
builder_options  step_id,
                 code VARCHAR(60)  -- стабильный ASCII, неизменяемый после первой ссылки:
                                   -- dest_ashgabat, nights_7, hotel_3star, hotel_yurt, pax_6_10
                 name/note JSON,
                 numeric_value INT NULL,        -- ночи 3/5/7/10/14, человек 1/2/4/8/12
                 price_modifier_minor BIGINT,   -- только ставки отелей
                 modifier_type ENUM('per_night','per_item','flat','none'), sort_order
pricing_rules    key_name UQ, value_minor BIGINT, unit, currency
                 -- base_fee 18000, city_fee 6000, activity_fee 4500,
                 -- default_nights 6, default_hotel_rate_minor 7800, default_pax 2
```

```
pax       = option(people).numeric_value       ?? rule(default_pax)
nights    = option(dates).numeric_value        ?? rule(default_nights)
hotelRate = option(hotel).price_modifier_minor ?? rule(default_hotel_rate_minor)
perPerson = nights*hotelRate + |dest|*rule(city_fee) + |activities|*rule(activity_fee) + rule(base_fee)
total     = perPerson * pax
```

Ничто здесь не читает `★` и не читает en-dash. Три значения по умолчанию важны не меньше ставок: именно они дают `1 296 $`, которые посетитель видит до первого клика.

**Ставки сборщика и цены отелей остаются разными колонками**, хотя сидовые значения совпадают (46/78/145/96/95 — это цена самого дешёвого отеля каждого класса). Иначе редактор, поправивший цену одного отеля, молча переоценит все открытые расчёты (D-22).

### Umrah (6)

```
umrah_trips        depart_at DATETIME UTC, return_at, signup_closes_at,
                   seats_total, seats_taken, duration_days, hotel_mekka, hotel_medina,
                   status ENUM('draft','open','full','closed','departed','completed'),
                   is_current, price_minor NULL, price_currency  -- цена только для админки
                   CHECK (seats_taken BETWEEN 0 AND seats_total)

umrah_program_days  + title/description/city JSON  -- в README их нет, а это весь контент страницы

                    -- photos_count и videos_count НЕ хранятся, только COUNT(*)
umrah_group_media   kind ENUM('photo','video'), media_id, caption JSON,
                    span_cols/span_rows, sort_order
```

У MySQL нет частичных индексов; генерируемая колонка `is_current_key` с UNIQUE — стандартный приём, гарантирующий не более одной текущей строки.

**Как `umrah_trips` управляет всем.** Текущий рейс **выводится**, а не запоминается: берётся рейс со статусом `open|full|closed` и ближайшей будущей `depart_at`; `is_current` существует только как ручное переопределение, если владелец хочет показать более поздний набор. Флаг, который админ должен не забыть переставить, — это флаг, который однажды окажется неверным. Статус вычисляется при чтении и дописывается кроном: чтение остаётся верным, даже если крон умер, а запись нужна, чтобы админские списки не расходились с сайтом.

| Условие                                      | Статус      | Что видит посетитель                                                                  |
| -------------------------------------------- | ----------- | ------------------------------------------------------------------------------------- |
| `now < signup_closes_at`, места есть         | `open`      | отсчёт, полоса, форма                                                                 |
| `seats_taken >= seats_total`                 | `full`      | отсчёт, полоса 100%, CTA → лист ожидания                                              |
| `now >= signup_closes_at`, `now < depart_at` | `closed`    | отсчёт, форма отключена с объяснением                                                 |
| `now >= depart_at`                           | `departed`  | **отсчёта нет.** «Группа в пути» + дата возвращения, сайт продвигает следующий `open` |
| `now >= return_at`                           | `completed` | кандидат в `umrah_groups` для `/suratlar`                                             |
| будущих рейсов нет вовсе                     | —           | «следующая группа будет объявлена», форма превращается в «сообщить мне»               |

Последние два состояния **не нарисованы** и случатся в первые же недели после запуска — Q-4.

**Индексы:** `(is_published, sort_order)` на всех публичных таблицах, `created_at` на `leads` и `umrah_signups`, `(group_id, kind, sort_order)` на `umrah_group_media`, функциональные по JSON-путям там, где админка сортирует по локализованному заголовку.

## 4. API

База `https://api.charva-travel.com/api/v1`. CORS — белый список, публичные сайты не шлют кук вообще.

```
GET  /global/settings|tours|tours/:slug|hotels|hotels/:slug|articles|articles/:slug
     |gallery|videos|reviews|faq|country|home|builder/config
GET  /umrah/settings|trip/current|package|ziyarat|ziyarat/:slug|program|groups|groups/:slug|home
GET  /choice
POST /global/builder/quote
GET  /forms/token          подписанный HMAC(issuedAt), без состояния
POST /global/leads · POST /umrah/signups
GET  /img/:name?w=         sharp на лету, дисковый кеш, immutable
GET  /health · /ready · /docs
```

Композитные `/global/home` и `/umrah/home` существуют, потому что иначе главная делает девять запросов на канале, который может быть плохим. Данные те же, собраны на сервере, кешируются одним куском.

**`POST /builder/quote`** принимает только **коды** вариантов, возвращает `perPerson`, `total`, `pax`, `nights`, `breakdown[]`, `missingSteps[]`, `isEstimate`. Одна реализация, два потребителя: `GET /builder/config` отдаёт таблицу ставок, клиент считает **той же функцией** для мгновенной реакции на клик, дебаунс-`POST` возвращает авторитетное число. Клиент не может разойтись с сервером, потому что второй реализации не существует. При отправке заявки сервер пересчитывает из БД и **игнорирует всё, что прислал клиент**.

**Антиспам, пять слоёв, без капчи** (D-19): rate limit 5/10 мин на IP и эндпоинт · honeypot-поле `website`, заполнено → `204` и ничего не пишем, никогда не сообщение об ошибке, которое научит бота · HMAC-ловушка времени: `formToken` — подпись момента выдачи, отвергается быстрее 3 с и медленнее 2 ч, без хранилища и куки · подавление дублей: `hash(endpoint + телефон)` за 15 минут возвращает **тот же** `leadId` и пишет одну строку · валидация телефона `libphonenumber-js`, туркменский `+993 6X XXXXXX`.

**Кеш:** в процессе, TTL 60 с по `route+query+lang`, сброс счётчиком поколений при записи из админки, `ETag` от хеша, `Cache-Control: public, max-age=60, stale-while-revalidate=300`. `/umrah/trip/current` кешируется так же, и это безопасно: клиент считает отсчёт локально от `departAt`, поэтому 60-секундная давность — это устаревшее число мест, а не сбитые часы.

**Медиа.** `@fastify/multipart` 20 МБ (видео — отдельный лимит), определение типа по магическим байтам, никогда по заявленному MIME, sharp: поворот → **удаление EXIF** (обязательно: это фотографии паломников, а EXIF несёт GPS) → WebP q86, максимум 2560px → `uploads/YYYY/MM/<sha256-12>.webp`. Производные генерируются по требованию в `uploads/.cache/` только для белого списка ширин. Видео: `ffprobe` для длительности, `ffmpeg` для постера и одного транскода 720p H.264, отдача nginx с `Accept-Ranges`.

## 6. Решения

| #        | Решение                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **D-1**  | Прототипы выигрывают по значениям, README — по поведению и структуре. Цифры «01»/«02» и списки языков на Choice **восстанавливаются**: массивы данных в прототипе уцелели, а тела рендера пусты — это подпись усечённого экспорта, а не смены дизайна. Незаконченный код — не то же самое, что противоречащий код.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **D-2**  | Адаптив, i18n и доступность пишутся вместе с разметкой в фазах 4–6. В silkgrain это же решение принято как D-19 после того, как ретрофит был оценён в 30–40 ч. Фаза 8 — наполнение и аудит, а не переделка.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **D-3**  | **Шесть пар токен/фон не проходят WCAG AA и правятся только по светлоте.** Замерено: `#B7A695` на `#FAF6EF` = **2,19:1**; `#93806E` на `#FAF6EF` = 3,51:1; `#7A8981` на `#F7F4EE` = 3,34:1; `#55655C` на `#F7F4EE` = 4,29:1; `#A9722C` на `#FAF6EF` = 3,83:1 (а он несёт надзаголовки 11px/700, которые не «крупный текст»); `#A8752F` на `#F7F4EE` = 3,68:1. Тон и насыщенность сохраняются, декоративное применение оставляет значения макета, `CONTRAST_PAIRS` + `tokens.test.ts` — контракт. Это единственное место, где план сознательно отступает от «пиксель-в-пиксель» — Q-7.                                                                                                                                                                                                                                                                                                                                                                       |
| **D-4**  | **`<head>` для краулеров и превью ссылок рендерит API в SPA-оболочку** — паттерн, который вы уже возите в Bakar (`spa.ts`): per-route заголовки, OG, JSON-LD, инлайн критического CSS, preload LCP, встроенный первый payload. Полный SSR для шестнадцати почти статичных маршрутов не окупается, а чистый CSR полностью ломает превью в Telegram и WhatsApp — а это основной канал распространения для этой аудитории. Пререндер на сборке — задокументированный запасной вариант.                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **D-5**  | **Переводимый контент — JSON-колонки `{ru,en,tr}` / `{tm,ru}`, а не `*_translations`**, вопреки README §7. Четыре причины. (а) Набор языков **разный у разных сайтов** — таблица `(entity_id, lang)` не умеет выразить «эта сущность бывает только RU/EN/TR», а типизированная JSON-форма умеет, на границе контракта. (б) **Частичный перевод — нормальное состояние**: реалистично сначала будет русский. Отсутствующая строка перевода — это NULL из LEFT JOIN, требующий явной цепочки запасных вариантов в каждом запросе; отсутствующий ключ JSON — пустая строка в известной форме, разрешаемая одной чистой протестированной `pickLocale()`. (в) Форма админки — по сущности с языковыми вкладками: один `PATCH` одной строки вместо upsert N строк. (г) Объём — несколько сотен строк, экономии на join просто нет. Валидируется `JSON_SCHEMA_VALID`. Обратимо механической миграцией, если появится пер-языковая публикация или роль переводчика. |
| **D-6**  | **Каждое зашитое маркетинговое число заменяется агрегатом.** «Показано N из 32», «32 маршрута», «46 отелей», «214 отзывов», «92% советуют», «68 групп», «2 840 паломников» считаются по опубликованным строкам. Сегодня они противоречат девяти строкам данных, а два числа для одного факта — на одно больше, чем нужно. Если владелец хочет маркетинговую цифру, она становится явным именованным переопределением в `settings` — Q-5.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **D-7**  | **Ни Redis, ни cluster: API работает одним fork-инстансом PM2.** Кеш и rate limit живут в процессе, а cluster умножил бы каждый лимит на число воркеров. Весь контент — несколько сотен строк; добавлять сервис, портативный бинарник, запись в compose и отдельный режим отказа ради кеша размером в сотни килобайт не стоит того. Redis станет оправдан в день появления фоновых задач или второго инстанса — не раньше.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **D-8**  | **Ни S3, ни MinIO: медиа — локальный диск + sharp + `/img?w=`**, ваш существующий конвейер из Bakar. `media.storage_key` хранит относительный ключ, а не URL, поэтому переезд в объектное хранилище — замена адаптера. Цена решения явная и попадает в `DEPLOY.md`: `uploads/` обязан быть в бэкапе, а приложение не масштабируется горизонтально, пока это не изменится.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **D-9**  | **Мёртвые данные трёх тарифов вычищаются, а не комментируются.** `packagesUnused` с ценой `8 575 TMT`, поле `pack` у мест зиярата и лид-абзацы Program и Route, ссылающиеся на тарифы. README §5 однозначен: умра одна, цен на сайте нет. «Оставим на всякий случай» — это ровно то, как цена однажды попадает на страницу.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **D-10** | **Варианты сборщика ключуются стабильными ASCII-кодами, `numeric_value` отделён от `price_modifier_minor`.** README смешивает «стоит X» и «означает число N»: `7 дней` — не цена. Коды неизменяемы после первой ссылки, поэтому турецкий перевод строки «3–5» не может сдвинуть цену.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **D-11** | **Клиент никогда не считает цену авторитетно, но считает её мгновенно — той же функцией.** Формула — чистая функция в `packages/contracts`; `GET /builder/config` отдаёт ставки, клиент применяет её на каждый клик, дебаунс-`POST` подтверждает. Разойтись не с чем: второй реализации нет. При отправке заявки сервер пересчитывает из БД.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **D-12** | **Цены Umrah не могут утечь структурно.** `umrah_trips.price_minor` существует для админки. В публичной Zod-схеме **ответа** такого поля нет, а `fastify-type-provider-zod` использует схемы ответа как сериализатор — случайный `select *` обрезается на проводе, а не «не должен случиться». Тест рекурсивно обходит JSON каждого публичного маршрута и падает на ключе, похожем на цену. Соглашение однажды забудут; сериализатор — нет.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **D-13** | **Текущий рейс выводится, `is_current` — только ручное переопределение; статус вычисляется при чтении и дописывается кроном.** Флаг, который надо не забыть переставить, окажется неверным ровно на той неделе, когда владелец в отъезде. Вычисление при чтении держит сайт верным даже при умершем кроне; запись нужна, чтобы админские списки не расходились. Шесть состояний, включая настоящий `departed`, заменяют молчаливое зажатие в нули.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **D-14** | **Шрифты — три WOFF2 из Bakar, под тестом покрытия глифов.** Тест важен: основная аудитория Umrah читает по-туркменски, а пропавшие `ň ý ž ä` — это «тофу» на самой важной странице, и никто, тестируя по-русски, этого не заметит. Объединение наборов: латиница + кириллица + туркменские `ä ň ö ş ü ý ž` + турецкие `ç ğ ı İ ş`. Тест в `pnpm test`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **D-15** | **Чипы фильтров строятся из данных, а не зашиваются.** `SELECT DISTINCT` по опубликованным строкам. Это структурно чинит пропавший чип `Jidda` (город в данных есть, чипа нет) и гарантирует, что ни один чип не приведёт к пустой сетке.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **D-16** | **Спаны мозаики — редакторская подсказка, прогоняемая через детерминированный упаковщик first-fit по видимому набору.** Спаны прототипа свёрстаны под нефильтрованные 14 элементов, поэтому любой фильтр оставляет дыры. First-fit устойчив к префиксу, поэтому «Показать ещё» дописывает плитки, не перекладывая уже показанные. Тот же упаковщик обслуживает мозаику групп Umrah, которая сегодня падает при более чем восьми подписях.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **D-17** | **Семь кандидатов в отдельные таблицы схлопываются в `content_blocks`.** Состав пакета, условия, «входит в цену», порядок записи, распорядок дня, факты о стране и шаги визы — одна и та же форма: упорядоченный список маленьких подписанных элементов, принадлежащих странице, ни с чем не соединяемых, с одинаковым UX в админке. Требования полей по `block_code` — размеченное объединение в contracts, так что типизация не теряется. `places_to_see` остаётся настоящей таблицей: у него обложка, слаг и текст.                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **D-18** | **Номера паспортов шифруются при хранении, каждое чтение пишется в журнал.** AES-256-GCM, ключ в окружении, поле отсутствует в списочных ответах, расшифровка только явным действием «показать», пишущим строку в `audit_log`. Это самое чувствительное поле в системе, и хендофф не упоминает его ни разу.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **D-19** | **Никакой сторонней капчи в первой версии.** Пять слоёв без состояния защищают форму, получающую единицы отправок в день. Turnstile добавил бы зависимость от Cloudflare с неочевидной доступностью из Туркменистана и отдельную поверхность согласия. Это задокументированная эскалация, а не значение по умолчанию.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **D-20** | **Админский SPA ходит в API same-origin по `admin.charva-travel.com/api`**, проксируемому nginx в тот же upstream. Тогда refresh-кука `SameSite=Strict` и привязана к админскому хосту — она никогда не уезжает на публичные сайты, и CSRF во многом исчезает без double-submit токена. Альтернатива `Domain=.charva-travel.com` рассылала бы админскую сессию на каждый публичный просмотр.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **D-21** | **`content_slots` — полноценная таблица.** 151 бриф `<image-slot>` становятся строками со статусом: недостающие фотографии превращаются из недокументированного блокера в видимый назначаемый чек-лист в админке, а каждая страница рисует фирменную заглушку с собственным брифом, пока снимка нет. Именно это делает проект собираемым и показываемым до съёмки.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **D-22** | **Ставки отелей в сборщике и цены отелей в каталоге остаются разными колонками**, хотя сидовые значения совпадают. Вывод одного из другого означал бы, что редактор, поправивший цену одного отеля, молча переоценил все открытые расчёты.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **D-23** | **Строки интерфейса живут версионируемыми JSON-файлами в репозитории, а не в БД.** README §9 просит экран «Переводы» с таблицей ключей. Копия интерфейса меняется вместе с вёрсткой, ревьюится вместе с ней и не должна иметь возможности сломать страницу в рантайме. В базе только **контент**. Экран переводов — в `BACKLOG.md`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **D-24** | Деньги — целые минорные единицы в `BIGINT`, форматирует только `Money` в `packages/contracts`. USD у Global, TMT у Umrah. Вся формула сборщика — целочисленная, поэтому расчёт воспроизводим точно.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **D-25** | Временные стоковые фото попадают в сиды с `source='stock'`, заполненным `attribution` и `is_placeholder=1`. Выкладка в прод блокируется, пока список временных фото в админке не пуст.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |

## 9. Верификация

После каждой фазы:

```bash
pnpm verify        # format:check + lint + typecheck + test + build, обязан выйти с 0
```

Дополнительно:

- **Ф0** — `dev-setup.ps1 -Action install` на чистой машине; побайтовая ASCII-проверка скриптов; `docker compose config` валиден
- **Ф1** — Storybook, ручная сверка с прототипом при 1280px, `tokens.test.ts`, тест глифов, проход клавиатурой, эмуляция `prefers-reduced-motion`
- **Ф2** — двойной `db:reset && db:migrate && db:seed`; тесты ограничений; `quote({})` = 1 296 $; grep на зашитую дату
- **Ф3** — интеграционные тесты против `charva_test`, **не** против моков: `STRICT_TRANS_TABLES`, уникальные индексы и CHECK существуют только в MySQL. Плюс тест на утечку цены и все пять слоёв антиспама
- **Ф4–Ф6** — проход по каждому маршруту, отправка каждой формы с проверкой Mailpit и строки в БД; смена `is_current` меняет три сайта; property-тест совпадения расчёта клиента и сервера
- **Ф7** — сквозной сценарий «редактор меняет каждое поле каждого экрана, грузит фото и видео, публикует» без единой правки кода
- **Ф8** — Lighthouse и axe на десктопе и мобильном по всем маршрутам; `hreflang`, `sitemap.xml`, превью ссылки в Telegram
- **Ф9** — `DEPLOY.md` сверху вниз на чистой машине; `deploy.sh` и следом `rollback.sh`; восстановление из бэкапа **вместе с изображениями**; перемотка видео
